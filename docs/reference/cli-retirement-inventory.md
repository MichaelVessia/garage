# Garage CLI retirement inventory

- Status: current migration inventory
- Audited: 2026-08-26
- Related decision: [ADR 0002](../adr/0002-consolidated-garage-mcp-delivery-edge.md)

Garage paths are relative to this repository. Paths beginning with `modules/programs/agents/` or `modules/programs/shell.nix` are relative to `/home/michaelvessia/nixos-config`.

## Executive disposition

Do not delete all CLIs in one change. The installed binaries are still the primary interface named by every corresponding nixos-config skill, and each skill also retains raw shell/curl compatibility scripts. Migrate and verify each skill against Executor first, then remove its Nix package and local secret exports, then remove its Garage CLI app. Keep the reusable `packages/<service>` package whenever Garage MCP still consumes it.

- **Best first retirement:** SABnzbd, because Garage MCP now has exact domain-shaped parity for all eight CLI operations and Executor approval policies for pause/resume/delete. The skill and shim still need migration.
- **Likely next candidates:** AdGuard, Caddy, Immich, Jellyfin, Jellyseerr, Prowlarr, Radarr, Sonarr, after curated parity and mutation-policy checks rather than merely relying on broad OpenAPI catalogs.
- **Retain/defer:** AutoCaliWeb, Tailscale, and TubeArchivist for the blockers below.

## Shared blockers and change surface

1. **nixos-config installation is centralized.** `modules/programs/common.nix:9-35` names all 12 CLIs, overrides each Garage flake package with regenerated Bun deps, and `modules/programs/common.nix:119` installs all of them on Linux. `modules/programs/garage-bun.nix:1-4,813-838` is generated and contains each app/package path. Remove entries only after skill migration; regenerate rather than hand-edit `garage-bun.nix`.
2. **Every skill remains installed.** `modules/programs/agents/shared.nix:18-34` includes these skills. Removing a CLI without rewriting its `SKILL.md`, README/references, and compatibility scripts leaves broken agent instructions.
3. **`@garage/cli-protocol` is not deletable with the apps.** Its owned responsibilities include config readers, JSON/list schemas, service-error helpers, JSON HTTP decode/error behavior, and recording test infrastructure (`packages/cli-protocol/CONTEXT.md:20-27,45-63`). Integration packages import these helpers directly, e.g. `packages/sabnzbd/src/http.ts:1-2`, `packages/sonarr/src/http.ts:1-2`, and analogous imports across all HTTP packages. Retain it initially or separately extract/rename non-CLI runtime capabilities before deleting CLI-only envelope/parser/runtime code.
4. **Garage release/build coupling is broad.** All 12 flake outputs are defined at `flake.nix:156-216`; root `package.json:23` runs compiled CLI and Nix release smoke; `scripts/cli-smoke.sh:1-34` checks executable envelope behavior; `scripts/live-cli-missing-env.test.ts:14-24,190-218` imports/runs the apps; and `scripts/cli-versioning.ts:23-68,287-288` plus `.github/workflows/release-cli-versions.yml:62-97` discovers, versions, and tags CLIs. Each retirement must update flake outputs, smoke tests, missing-env tests, versioning/release assumptions, docs/context map, lock/Nix artifacts, and generated outputs.
5. **No evidence of unrelated non-skill CLI automation was found** outside the Nix installation, Garage release/test harness, and the skill/script trees. Human ad-hoc use cannot be proven absent; keep a rollback window or confirm before final package deletion.

## Safe retirement sequence

For one service at a time:

1. Rewrite its nixos-config skill to call Executor/Garage MCP and remove raw local credential access where possible.
2. Exercise every curated read and mutation; add Executor `require_approval`/`block` rules for unsafe calls.
3. Remove that name from `garageCliNames`; preserve unrelated dirty nixos-config work.
4. Remove shell exports only after repository-wide search proves no remaining local workflow uses them.
5. Remove `apps/<service>-cli`, but retain `packages/<service>` when MCP or other production code uses it.
6. Update Garage flake, scripts/tests, release automation, lock/Nix generated artifacts, documentation/context routing, and changesets as required.
7. Run Garage focused checks, `bun run validate`, and `bun run validate:release`; run the nixos-config formatting/evaluation/build checks required by its instructions.
